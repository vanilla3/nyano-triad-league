# Work Order: 049 盤面/ステージのビジュアル磨き込み（カードに負けない“置き台”）

## 1) 背景 / 目的（ユーザー視点）

カードの質感が上がってきた一方で、対戦中に最も長く見続ける **盤面（ボード）とステージ（背景/枠/トレイ）** が
まだ「検証ツールっぽい」印象を残しています。

本WOの狙いは、派手さではなく **素材感・奥行き・視線誘導・状態変化の明確さ** を上げ、
「置きたくなる」「触りたくなる」土台を作ることです。

---

## 2) スコープ

### In scope
- Mint UI の盤面/ステージの見た目強化（CSS中心）
  - `apps/web/src/mint-theme/mint-theme.css`
  - `apps/web/src/components/BoardViewMint.tsx`
  - `apps/web/src/components/DuelStageMint.tsx`
- 状態の視覚化（置ける/置けない/選択中/確定/フリップ/連鎖）の“読みやすさ”維持
- `data-vfx`（off/low/medium/high）と `prefers-reduced-motion` の尊重

### Out of scope
- ルール/エンジン/通信/URL互換の変更
- Pixi/Three などの大規模導入（必要なら別WO）
- 新規の大型画像アセット導入（ライセンス不明は不可）
  - どうしても必要なら「自作 or 権利クリア済み」のみ、最小枚数で

---

## 3) 目標（Deliverables）

- [ ] 盤面全体が「1つの玩具/台座」として見える（外枠・厚み・ハイライトが統一）
- [ ] セルの状態が“色だけ”に依存せず、形/陰影/微小モーションで判別できる
- [ ] 重要要素（手札/盤面/次の行動）の視線誘導が自然
- [ ] `data-vfx=off/low` で軽量、`medium/high` で微細な上質さ（ノイズ/グリント等）が追加される
- [ ] モバイル幅（~390px）でも破綻しない

---

## 4) デザイン方針（桜井っぽい基準）

- 同じ種類の状態変化は、同じテンポ（時間/イージング）に寄せる  
- “強い演出” は常時ではなく **意味がある瞬間だけ**  
- 見た目を盛るほど、**情報の階層（何が大事か）** を壊しやすい → まず読みやすさ優先

---

## 5) 実装方針（Approach）

### A. 台座（Board Shell）の統一
- 盤面外枠に「厚み」「縁の反射」「角のアクセント」を付け、カードの質感と釣り合う“台”にする
- 影は大きくしすぎず、`box-shadow` の多重は控えめに（重い filter は避ける）

### B. セルの状態を“形”で伝える
- 置けるセル: 少し浮く + 触ってよい輪郭（rim）
- 置けないセル: へこみ + コントラスト低下（ただし読める）
- 選択中: 枠の強調 + 軽いパルス（`data-vfx` で抑制）
- 確定/フリップ: 既存アニメを活かしつつ、余韻（glow）を短く入れる（off/low では無効）

### C. 背景の“死んでない”感
- 既存の軽量背景（CSS）を活かし、盤面周辺だけ “微細ノイズ/グリッド” を薄く重ねる
- reduced-motion ではスクロール/ドリフトを止める

---

## 6) 受け入れ条件（Acceptance Criteria）

1. `/battle-stage` および `/match?theme=mint`（または Mint UI が出る画面）で
   - 盤面がカードに負けない「台座感」を持つ
   - 置ける/置けない/選択中/フリップ が一瞬で判別できる

2. `data-vfx=off` で
   - 常時のノイズ/グリント/強い glow が無効化される
   - それでも見た目が成立している

3. `prefers-reduced-motion: reduce` で
   - 不要な常時アニメが止まる（機能は維持）

---

## 7) 検証（Verification）

- `pnpm -C apps/web typecheck`
- `pnpm -C apps/web lint`
- `pnpm -C apps/web test`
- `pnpm -C apps/web build`

手動:
- デスクトップ/モバイル幅で盤面を操作し、状態が読みやすいか確認
- `?vfx=off` 相当（`documentElement.dataset.vfx="off"`）で重さ/見た目を確認
